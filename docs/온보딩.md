# face 콕 — 팀원 온보딩 문서

정리 기준일: 2026-09-03

이 문서는 로컬 개발 환경을 세팅하는 방법을 정리한다. 인프라 전체 구조는 [인프라설계.md](./인프라설계.md)를 먼저 참고한다.

## 1. 개발 방식 요약

- **초기 개발은 전부 로컬에서 진행**한다. AWS 인프라는 초기 기능 개발이 끝난 뒤에 붙인다.
- 프론트(React/Next.js)는 지금부터 계속 **main 브랜치가 Vercel에 배포**된다.
- 백엔드(Spring Boot)는 로컬 개발이 끝난 뒤 AWS에 처음 올라가고, 그때부터 실제 인프라 테스트가 시작된다.
- **팀원마다 로컬에 자기 DB/Redis를 띄운다.** Railway 같은 공유 원격 DB는 쓰지 않는다 — 여러 명이 동시에 같은 데이터를 건드리면 충돌하기 때문이다. 매칭·채팅처럼 두 사용자가 필요한 기능은 본인 로컬 DB 안에 테스트 계정 2개를 만들어서 확인한다.
- **Docker Compose**로 MySQL·Redis를 로컬에 띄워서, 팀원 전체가 같은 버전·같은 설정을 쓴다.
- **Flyway**로 DB 스키마를 버전 관리한다 — 데이터는 각자 달라도 테이블 구조는 항상 팀 전체가 동일하게 유지된다.

## 2. 사전 준비물

| 도구 | 용도 | 비고 |
| --- | --- | --- |
| Docker Desktop | 로컬 MySQL·Redis 컨테이너 실행 | 실행 후 백그라운드에 켜져 있어야 함 |
| JDK 21 (또는 팀에서 정한 LTS 버전) | 백엔드(Spring Boot) 실행 | Amazon Corretto 권장 |
| Node.js 20 이상 | 프론트(Next.js) 실행 | 기존 레포 그대로 사용 |
| Git | 레포 관리 | |
| IntelliJ IDEA (백엔드) / VS Code (프론트) | 권장 IDE | 필수는 아님 |

## 3. 레포 구조

레포를 FE/BE로 분리할 예정이다 (분리 시점은 별도 공지). 분리 전까지는 기존 레포 구조를 따르고, 분리 이후 이 문서를 갱신한다.

- **프론트 레포**: 기존 React/Next.js 코드 그대로
- **백엔드 레포(신규)**: Java Spring Boot, 아래 3~5번 세팅 대상

## 4. 로컬 DB·Redis 띄우기 (Docker Compose)

백엔드 레포 루트에 아래 형태의 `docker-compose.yml`을 둔다 (실제 값은 백엔드 레포 세팅 시 확정).

```yaml
services:
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_DATABASE: facecook
      MYSQL_USER: facecook
      MYSQL_PASSWORD: local-dev-password
      MYSQL_ROOT_PASSWORD: local-dev-root-password
    ports:
      - "3306:3306"
    volumes:
      - mysql-data:/var/lib/mysql

  redis:
    image: redis:7
    ports:
      - "6379:6379"

volumes:
  mysql-data:
```

실행:

```bash
docker compose up -d
```

## 5. Flyway 마이그레이션

백엔드 레포에 `src/main/resources/db/migration/` 아래 `V1__init.sql` 형태로 스키마 변경 이력을 쌓는다.

- 새 테이블·컬럼이 필요하면 **기존 마이그레이션 파일을 고치지 말고, 새 버전 파일을 추가**한다 (`V2__add_push_subscription.sql` 식)
- 로컬에서 스프링 부트 앱을 실행하면 부팅 시 Flyway가 자동으로 최신 버전까지 마이그레이션을 적용한다
- 팀원이 새 마이그레이션 파일을 pull 받으면, 다음 로컬 실행 시 자동으로 반영된다 — 수동으로 DB를 직접 고치지 않는다

## 6. 환경변수 (로컬 개발용)

백엔드 레포 루트에 `.env` 또는 `application-local.yml`로 아래 값을 채운다 (실제 값은 백엔드 세팅 시 팀 내부 공유 — 민감한 값은 이 문서에 적지 않는다).

```
DB_URL=jdbc:mysql://localhost:3306/facecook
DB_USERNAME=facecook
DB_PASSWORD=local-dev-password
REDIS_HOST=localhost
REDIS_PORT=6379
SESSION_SECRET=(로컬 개발용 임의값, 운영값과 다르게)
SMTP_HOST=smtp-relay.brevo.com
SMTP_USER=(팀 내부 공유)
SMTP_PASS=(팀 내부 공유)
VAPID_PUBLIC_KEY=(로컬 개발용 별도 발급값)
VAPID_PRIVATE_KEY=(로컬 개발용 별도 발급값)
```

**운영(AWS) 환경의 실제 비밀값과 로컬 개발용 값은 다르게 관리한다.** 운영 값은 AWS Secrets Manager에서만 관리하고, 이 문서나 코드에 하드코딩하지 않는다.

## 7. 실행 확인

- 백엔드: `docker compose up -d` → 스프링 부트 앱 실행 → 콘솔에 Flyway 마이그레이션 로그와 함께 정상 기동 확인
- 프론트: `npm install` → `npm run dev` → 로컬 백엔드 주소를 바라보게 설정된 상태로 화면 확인

## 8. 자주 겪는 문제

| 증상 | 원인/해결 |
| --- | --- |
| 스프링 부트 기동 시 DB 연결 실패 | Docker Desktop이 켜져 있는지, `docker compose up -d`가 정상 실행됐는지 확인 |
| 3306/6379 포트 충돌 | 로컬에 이미 다른 MySQL/Redis가 떠 있는 경우 — 기존 프로세스 종료 또는 compose 파일 포트 변경 |
| Flyway 마이그레이션 오류 | 기존 마이그레이션 파일을 수정했을 가능성 — 새 버전 파일로 추가했는지 확인 |
| 매칭 상대 테스트가 안 됨 | 본인 로컬 DB에 테스트 계정이 1개뿐인 경우 — 계정 2개를 만들어서 서로 매칭 테스트 |

## 9. 이 문서 범위 밖

- 실제 백엔드 레포 생성 후 정확한 `docker-compose.yml`, 마이그레이션 파일 경로, 환경변수 키 이름은 이 문서를 갱신해서 반영한다
- API 명세, ERD는 별도 문서에서 다룬다
- 브랜치·커밋·PR 컨벤션은 별도 확정 후 추가한다
