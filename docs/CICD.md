## 1. 프론트 (facecook-fe)

- **Vercel이 `main` 브랜치를 자동 배포**한다. PR을 `main`에 머지하면 그걸로
  배포가 끝난다 — 별도 파이프라인 설정이 필요 없다
- PR을 올리면 Vercel이 프리뷰 배포(preview URL)도 자동으로 만들어준다 —
  리뷰할 때 그 URL로 실제 화면을 확인할 수 있다

## 2. 백엔드 (facecook-be)

**아직 배포 파이프라인이 없다.** [인프라설계.md](./인프라설계.md) 6번 원칙대로,
초기 개발은 전부 로컬(Docker Compose)에서 진행하고, 로컬 개발이 어느 정도
끝난 뒤에 처음 AWS에 올리면서 그 시점부터 파이프라인을 만든다.

목표로 하는 흐름(확정 아님, 방향만):

```text
PR 생성 → 빌드 + 테스트(JUnit) 자동 실행
       ↓ (통과 시)
main 머지 → Docker 이미지 빌드 → EC2(2대)에 배포
```

- 빌드 도구: Gradle(Groovy DSL)
- 배포 단위: Docker 컨테이너 ([인프라설계.md](./인프라설계.md) 6번 — 로컬·서버
  실행 환경을 동일하게 맞추기 위함)
- 어떤 CI 도구를 쓸지(GitHub Actions 등), 두 EC2에 어떻게 무중단으로
  배포할지는 **미정** — 첫 AWS 배포 시점에 확정한다

## 3. DB 마이그레이션

- Flyway로 스키마 버전을 관리한다 ([온보딩.md](./온보딩.md) 5번)
- 새 스키마 변경은 항상 새 버전 파일을 추가하는 방식이고, 기존 마이그레이션
  파일은 수정하지 않는다
- 배포 파이프라인에 마이그레이션 자동 적용을 넣을지, 수동으로 확인 후
  적용할지는 **미정**

## 4. 이 문서 범위 밖

- 무중단 배포(블루/그린, 롤링) 방식
- 배포 실패 시 자동 롤백 여부
